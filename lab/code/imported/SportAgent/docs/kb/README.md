# 知识库 (Knowledge Base) 文档

本目录详细记录了 SportAgent 知识库中存储的静态知识。这些知识以 JSON 格式存储在 `data/raw/` 目录下，是 Agent 进行推理、过滤和计划生成的确定性依据。

## 核心知识模块

| 模块名称     | 对应文件                    | 职责                                                                   |
| :----------- | :-------------------------- | :--------------------------------------------------------------------- |
| **食材库**   | `nutrition.json`            | 存储各类食材的宏量营养素（热量、蛋白、碳水、脂肪）及饮食标签。         |
| **食谱库**   | `recipes.json`              | 存储预定义的健美/健身食谱，含步骤、默认配比及替代方案。                |
| **动作库**   | `exercises.json`            | 存储数百个训练动作，含器材要求、主/次肌肉群、难度及伤病禁忌。          |
| **营养原理** | `nutrition_principles.json` | 存储饮食限制（如 Vegan, Keto）的规则、替换逻辑及各目标的宏量比例建议。 |
| **训练规则** | `rules.json`                | 定义训练阶段（增肌、减脂等）的参数、频率建议及动作编排逻辑。           |
| **人体解剖** | `anatomy.json`              | 肌肉群定义及其层级关系（用于伤病影响分析）。                           |
| **伤病画像** | `injury_profiles.json`      | 预定义的伤病类型及其对应的解剖学标签。                                 |

## Agent 与知识映射矩阵 (Usage Mapping)

为了后续更新知识库，了解具体哪些 Agent 依赖哪些数据至关重要：

| 知识文件                    | PlannerAgent | CookingAgent | Onboarding / CLI | 备注                  |
| :-------------------------- | :----------: | :----------: | :--------------: | :-------------------- |
| `nutrition.json`            |      -       |   **核心**   |        -         | 提供食材基础数据      |
| `recipes.json`              |      -       |   **核心**   |        -         | 提供食谱模板          |
| `exercises.json`            |   **核心**   |      -       |        -         | 提供训练动作池        |
| `anatomy.json`              |   **核心**   |      -       |        -         | 决定组数上限/恢复逻辑 |
| `rules.json`                |   **核心**   |      -       |       引用       | 训练阶段与分化逻辑    |
| `nutrition_principles.json` |     引用     |   **核心**   |        -         | 宏量素配比与餐型定义  |
| `injury_profiles.json`      |   **核心**   |      -       |     **核心**     | 伤病标准化映射        |

- **核心 (Core)**: 该 Agent 的主要类库逻辑直接加载并解析此文件。
- **引用 (Reference)**: 知识内容被作为 Context 注入 Prompt，引导 LLM 生成。

## 知识库的作用

1. **确定性过滤**：Agent 在调用 LLM 前，会先基于知识库过滤出用户「能做」的动作和「能吃」的食谱。
2. **宏量素核算**：LLM 仅负责推荐食材组合，最终的所有营养数值计算均以知识库为准，通过 `_overwrite_macros_deterministic` 确保精度。
3. **安全边界**：通过动作库中的 `contraindications`（禁忌症）字段，系统能够自动阻断不安全的训练建议。
