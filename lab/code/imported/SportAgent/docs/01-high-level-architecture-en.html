System Architecture

AI Fitness System

A personalized fitness management system powered by LLMs and VLMs. Two core agents, three development phases, one goal: the user only needs to execute.
01 Two Core Agents
🏗️
Planning Agent
LLM-POWERED · PLANNING & SCHEDULING
Owns planning and management across the full fitness lifecycle. Starting from the user's body metrics, goals, and schedule, it generates training plans and nutrition programs at multiple levels of granularity (year → month → week → day → meal/exercise level). Through continuous interaction, it dynamically adjusts the plan to match real-life changes. Core sub-agents include CookingAgent (nutrition planning), GYMAgent (training orchestration), and KBAgent (self-evolving knowledge base).
SYNC
👁️
Vision Agent
VLM-POWERED · VISUAL FEEDBACK
Owns real-time visual understanding and feedback. It analyzes workout videos to identify movement patterns, compares them against a gold standard, and returns precise correction cues. It recognizes ingredients and estimates calories from food photos, and it tracks body changes from periodic physique photos. The Vision Agent feeds its outputs back into the Planning Agent to form a complete closed loop.

03 Phase 1 Roadmap: Planning Agent
v0.1.0 · Static Planning — Foundational Plan Generation
User Onboarding + Plan Generation
The user provides personal information through guided Q&A, including body metrics, goals, available equipment, injuries, dietary restrictions, and daily routine. PlanAgent uses the knowledge base to generate a personalized weekly training plan and daily nutrition program. A multi-round generate → validate → revise loop ensures plan quality.
PlanAgent
v0.1.x · Static Planning — Fine-Grained Guidance
CookingAgent + GYMAgent Fine-Grained Guidance
On top of the base Plan, specialized sub-agents generate far more detailed guidance. CookingAgent produces concrete recipes, ingredient substitutions, and grocery lists. GYMAgent produces training details such as execution cues, weekly progression parameters, and warm-up/stretching flows. The Plan is the skeleton; Guidance is the flesh.
PlanAgent CookingAgent GYMAgent
v0.2.x · Dynamic Interaction — User Corrections and Adjustments
Conversational Adjustments + Cascading Global Updates
Users can correct and adjust the content of the Plan and Guidance through natural conversation ("I want noodles today", "I have to work late on Wednesday and can't train"). The key challenge is that a local change often requires a global update: reducing one training day means redistributing weekly volume, and changing one meal means rebalancing nutrition across the rest of the day. The agent must perform and log these cascading updates automatically.
PlanAgent CookingAgent GYMAgent UserDialog
v0.2.x · Dynamic Interaction — Schedule Awareness
Calendar / Cycle / Work Schedule Integration
By importing ICS files or connecting calendar APIs, the agent can perceive the user's real schedule: assign lighter workouts on meeting-heavy days, switch to hotel-friendly bodyweight plans during travel, and automatically adjust training intensity and nutrition strategy during different cycle phases. The system evolves from "the user tells me what changed" to "I detect what changed proactively."
PlanAgent CalendarSync
v0.3.x · Self-Evolution — Automatic Knowledge Base Updates
KBAgent: Learning from the Internet + Adapting to User Preferences
KBAgent is responsible for the continuous evolution of the knowledge base in two directions: (1) ingesting the latest validated knowledge in nutrition and exercise science from the internet, books, and papers; and (2) adapting the emphasis of the knowledge base based on the user's historical conversations and preferences. For example, if the user frequently asks vegetarian questions, KBAgent will proactively deepen its vegetarian nutrition knowledge.
KBAgent PlanAgent
v0.4.x · Monitoring & Feedback — Closed-Loop Tracking and Correction
MonitorAgent: Expected vs Actual + Continuous Course Correction
MonitorAgent tracks what the user actually does, including workout completion, real food intake, and changes in weight or body-fat percentage. It maintains a dashboard of expected metrics vs actual metrics. It has two core objectives: (1) keep reality as close as possible to the intended plan, and (2) keep key indicators moving in a positive direction. When deviations exceed a threshold, it automatically triggers PlanAgent to update the plan, forming a complete closed-loop feedback system.
