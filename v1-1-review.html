02 已解决的问题 ✓
✓ 热量盈余从 ~1100 kcal 修正为 ~300 kcal
TDEE 2197 → 目标 2497，盈余约 300 kcal，符合初学者增肌的推荐范围。蛋白质 140g (2g/kg) 也是标准推荐。
✓ 每个动作都有了起始重量建议
如哑铃高脚杯深蹲 10-15kg、哑铃卧推 10-15kg 每侧等，基于 beginner_moderate 的力量评估给出了合理范围。
✓ 每日都有针对性的热身和拉伸方案
热身和拉伸不再笼统，而是针对当天训练的肌群设计了具体动作和时长。
✓ 加入了 4 周渐进规划
第 1 周建立动作模式、第 2 周保持不变、第 3 周渐进超负荷、第 4 周减量。这是一个完整的训练小周期。
✓ 饮食限制得到了尊重
乳糖不耐受 → 豆浆替代牛奶、无乳蛋白粉；不吃油腻 → 饮食推荐以清淡烹饪为主。

04 进一步改进建议
系统 伤病信息需要更细的粒度
当前记录了 wrist_injury 但没有区分伤病状态（急性 / 恢复中 / 陈旧伤）和严重程度。这直接影响动作筛选的逻辑——急性手腕伤需要完全回避手腕负重动作，而陈旧伤可能只需要避免特定握法（如正握换成对握）。系统已经做了一些适配（如选择锤式弯举而非正握弯举），但可以更系统化。建议在信息收集时增加伤病状态和严重程度的评估。
内容 饮食方案需要替换选项和热量验证
当前只有一套饮食方案，对大多数人来说不可持续。建议每餐提供 2-3 个等热量替换选项（如"鸡胸肉 150g 可替换为：鱼肉 180g / 虾仁 200g / 豆腐 250g"）。同时，agent 应该在生成饮食建议后验证推荐食物的总热量是否接近 2497 kcal 的目标，避免出现推荐食物加起来只有 1800 或高达 3000 的情况。
体验 输出格式需要支持"每日视图"
当前输出是一个完整的周概览，但用户的实际使用场景是"今天练什么"。建议 agent 的输出格式拆分为独立的每日对象（如 JSON 数组），每个对象包含该天的完整信息（热身、训练、拉伸、饮食）。这样前端可以直接渲染"今日训练卡"，用户不需要在一个长文档中寻找今天的内容。
内容 每个动作应附带 1-2 句执行要点
当前计划列出了动作名称、重量、组次数，但没有简短的动作要点。对于初学者来说，"哑铃罗马尼亚硬拉"这个名字本身就可能让人困惑。每个动作附带一句核心提示（如"背部保持平直，臀部向后推，感受腘绳肌拉伸"）会显著降低执行门槛。这些提示可以存在动作库的 cues[] 字段中。
系统 TDEE 应区分训练日和非训练日
当前 TDEE 使用单一值 2197 kcal（基于久坐活动系数）。但实际上，训练日的能量消耗会比非训练日高出 300-500 kcal。更精确的做法是：非训练日 TDEE ~2200，训练日 TDEE ~2500-2600，然后分别设定训练日和非训练日的热量目标。这在 V1 阶段可能不是必须的，但对于进阶版本来说会让营养指导更精准。
05 总评
B+
从上一版的 C+ 提升到了 B+，进步显著
这个版本已经是一个"可以用"的计划了。如果一个初学者拿到这个计划，他能够基本按照它去训练和饮食，不太会犯严重的错误。热量和营养目标合理，动作选择安全且有针对性，有了渐进规划的框架。

要从 B+ 到 A，主要差距在三个方面：一是饮食方案的可执行性和灵活性（替换选项、热量验证），二是每个动作的执行指导（动作要点提示），三是输出格式的优化（从周概览到每日训练卡）。这些改进不需要改变系统架构，都是在现有基础上的内容和格式增强。

另外值得一提的是，四周训练规划的加入是一个很好的方向，它让系统从"一次性的计划生成器"开始向"持续的训练管理者"转变。这为 V2（动态更新与主动交互）打下了基础。
