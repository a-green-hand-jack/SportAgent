02 本版新增的改进 ✓
新增 引入了杠铃复合动作
杠铃深蹲和杠铃臀推的加入充分利用了用户的可用器材，杠铃复合动作是力量增长和肌肉发展最高效的训练方式。同时加入了坐姿绳索划船和绳索面拉等 cable machine 动作，器材利用率显著提高。
新增 训练量自动验证机制
系统在生成计划后自动统计了每个主要肌群的周训练量，并与推荐最低值做了对比。日志显示 Volume validation: 8 muscle group(s) below target。虽然验证结果显示有肌群不达标（统计准确性存疑，见下方分析），但这个验证机制本身是一个关键的架构进步。
新增 饮食替换选项
每一餐都提供了替换方案（如"鱼肉 180g / 豆腐 250g / 牛肉 120g"），训练前后的营养指导也更具体了。乳糖不耐受和不吃油腻的限制在所有替换选项中都得到了尊重。
改善 训练分化更清晰，动作更丰富
五天分化逻辑更明确（下肢股四头肌主导 / 上推 / 上拉 / 下肢臀腿主导 / 全身复合），动作种类更丰富，涵盖了杠铃、哑铃、绳索和自重四种训练模式。
03 核心问题：训练量统计可能有 Bug
Bug 肌群训练量统计与计划内容不一致
底部验证显示 shoulders 本周仅 3 组，但实际计划中：Day 2 有肩推 3 组 + 飞鸟 3 组（胸飞鸟但前三角有参与） + 三头臂屈伸 3 组（长头涉及肩）+ 前平举 3 组，Day 3 有反向飞鸟 3 组，Day 5 有侧平举 3 组 + 反向飞鸟 3 组。仅直接三角肌训练就至少 9-12 组。 类似地，hamstrings 显示 3 组，但 Day 1 有罗马尼亚硬拉 3 组（主要腘绳肌动作），Day 4 有杠铃臀推 3 组 + 弓步蹲 3 组（腘绳肌次要参与）。
诊断 可能的原因
最可能的原因是动作库中的肌群标注不完整。例如 Dumbbell Shoulder Press 的 primary_muscle 可能被标注为 "shoulders" 但验证逻辑在检查时用的 key 是 "deltoids" 或 "anterior_deltoid"，导致计数时没有匹配上。另一种可能是验证逻辑只统计了 primary_muscle 而忽略了 secondary_muscles，导致像罗马尼亚硬拉（primary: glutes, secondary: hamstrings）这样的动作没有被计入 hamstrings 的训练量。建议检查两个地方：一是动作库的肌群标签是否使用了统一的命名规范，二是验证逻辑是否同时统计了 primary 和 secondary 肌群（secondary 可以按 0.5 的系数计算）。
04 其他改进建议
重要 起始重量范围仍然太宽
杠铃深蹲标注"空杆 20kg 或 30-40kg"，20kg 到 40kg 是一倍的差距。对于初学者来说，他到了健身房还是不知道该放几片杠铃片。建议改为更明确的指导："从空杆 20kg 开始，如果第一组能轻松完成 12 次，加到 30kg；如果 30kg 也能稳定完成 10 次以上，用 35kg"。或者在信息收集时增加一个简单的力量测试问题。
建议 手腕保护提示应该跟着动作走
底部有通用的手腕注意事项，但用户在执行具体动作时不会去翻底部。建议在每个可能影响手腕的动作（如飞鸟、弯举、卧推）旁边直接标注一个简短提示，如"⚠️ 手腕保持中立"。这样用户每做一个动作就能看到提醒。
建议 每个动作需要 1-2 句执行要点
计划里有动作名称、重量、组次，但没有动作要点提示。"杠铃深蹲"对初学者来说光名字就可能让人紧张，如果旁边有一句"脚与肩同宽，下蹲时膝盖与脚尖同向，挺胸收腹"，执行门槛会大大降低。这些 cues 可以预存在动作库中。
05 下一步架构建议：生成-验证-修正循环
当前系统是"单次生成"模式：LLM 生成一次计划 → 系统验证一次 → 输出结果。验证发现了问题（8 个肌群低于目标），但没有自动修复。下一步最有价值的改进是把这个过程变成一个多轮循环。

总结与下一步

这一版的计划在内容质量上已经非常接近可以交付给用户的水平。营养计算合理、动作选择丰富且充分利用了可用器材、饮食方案有替换选项、热身拉伸具体到位、有四周渐进框架。如果一个初学者拿到这个计划，他能够有效地开始训练。

当前的主要差距已经从"计划内容质量"转移到了"系统能力"——训练量验证存在统计 bug、验证发现问题后没有自动修正、起始重量范围需要更精确。这些都是系统层面的改进，而不是 LLM prompt 层面的改进。

建议的下一步优先级

P0 修复训练量验证的统计 bug（检查肌群命名一致性和 primary/secondary 计算逻辑）
P1 实现"生成-验证-修正"循环，让 agent 在验证不通过时自动调整计划
P2 在动作库中为每个动作添加 cues（执行要点）和手腕/伤病相关的特殊提示
P3 优化起始重量建议逻辑——要么缩小范围，要么提供阶梯式的判断指导
P4 生成四周的具体计划（而非仅文字描述的渐进框架）
