V1 知识库架构设计

V1 的核心任务是"根据用户信息生成个性化计划"。知识库是实现这个任务的关键基础设施——它决定了系统的专业性、安全性和输出质量的下限。
01 知识的三层结构
结构化数据
STRUCTURED DATA
确定性的、可查询的数据。不需要 LLM 来"理解"，直接用于筛选和计算。这是系统的事实基础。
动作库 80-120个 目标肌群映射 器材需求 难度分级 食物营养数据 热量/蛋白质/碳水/脂肪 动作禁忌标签
规则与原则
RULES & PRINCIPLES
经过专业审核的决策依据。以约束条件的方式注入 LLM 的推理过程，确保输出符合运动科学的基本原则。
训练容量原则 渐进超负荷 热量缺口/盈余范围 蛋白质摄入标准 训练频率上限 初学者保护规则 恢复时间要求 分化训练编排
参考文档
REFERENCE DOCS
更完整的知识文本，通过 RAG 检索在需要时提供给 LLM。V1 阶段可以较薄，后续版本逐步丰富。
训练教材摘要 营养指南 常见问题 FAQ 伤病预防指南 V1可选
♟️
知识库是棋盘和规则，LLM 是棋手。
棋手在规则允许的范围内自由发挥，但永远不能走出棋盘。

核心原则：安全边界由知识库的确定性逻辑保证，个性化与创造性由 LLM 保证

知识库负责（确定性）

哪些动作对这个用户是安全的？每天应该摄入多少热量和蛋白质？每个肌群每周最少和最多多少组训练量？初学者的前 N 周有哪些限制？这些问题的答案不应该依赖 LLM 的随机性。

VS

LLM 负责（创造性）

在可用动作池中如何搭配出一个逻辑连贯的训练日？怎样安排动作顺序让训练效率最高？如何把营养目标转化成具体的一日三餐建议？怎样用自然语言解释计划的设计思路？

03 数据从哪里来
🏋️
动作库
覆盖 80-120 个主流动作即可满足绝大多数用户需求。可从 ExRx.net、Wger（开源）等公开数据库整理，加人工审核补充。每个动作需要标注：目标肌群、器材需求、难度分级、禁忌人群、动作要点。
示例字段：name, primary_muscle, secondary_muscles,
equipment, difficulty, contraindications[], cues[]
🥗
营养数据
接入 USDA FoodData Central 或中文食物成分数据库。V1 阶段不需要完整的食谱库，重点是提供常见食物的营养成分数据，让 LLM 可以据此搭配饮食建议。
示例字段：food_name, serving_size,
calories, protein_g, carbs_g, fat_g, fiber_g
📏
规则集
这是最需要人工投入的部分。请 1-2 位有经验的教练审核整理一套基础规则集。V1 先覆盖最常见的 80% 用户画像：健康成年人、初级到中级水平、增肌/减脂/体态改善三个目标。
示例规则：减脂期每日热量缺口 300-500kcal
每肌群每周至少 10 组有效训练容量
初学者前 8 周不安排 1RM 测试
04 V1 的知识库边界

V1 必须包含

完整的基础动作库（80-120 个动作，含属性标注）。基本的营养数据（至少覆盖 500+ 种常见食物）。核心训练原则规则集（覆盖增肌/减脂/体态改善三大目标）。初学者安全保护规则（禁忌动作过滤、负荷限制）。基础的热量和宏量营养素计算公式（BMR、TDEE、蛋白质需求）。

延后到 V2+

互联网食谱自动抓取与整合。高级周期化编排知识（比如 DUP、Block Periodization 的具体实施细节）。特殊人群知识（孕妇、老年人、特定疾病患者）。运动补剂知识。RAG 检索系统（V1 可以先把规则直接写进 prompt，V2 再做检索）。

V1 知识库的设计核心总结

V1 的知识库策略可以概括为：结构化数据提供事实，规则集提供约束，LLM 提供智能。三者的分工要清晰——不要让 LLM 去做本应确定性完成的事情（比如计算热量），也不要试图用规则去替代 LLM 擅长的事情（比如把训练计划组织成连贯的文本）。

V1 的知识库不需要大，但需要准确且结构清晰。80 个经过仔细标注的动作，比 500 个粗糙标注的动作有价值得多。一套经过教练审核的核心规则集，比从网上爬来的 1000 篇未经验证的文章有价值得多。先小后大，先人工后自动。
