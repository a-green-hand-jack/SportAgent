# SportAgent 相似项目与创新空白 Deep Research

## Objective

找到 SportAgent 应复用、舍弃和真正创新的部分，为 build-vs-buy、v1 范围与后续实验提供可审计证据。

## Success criteria

- 覆盖直接相似项目、相邻开源基础设施、商业对标和相关论文；
- 区分基础设施与核心创新，并给出 adopt / wrap / retain / delete 判断；
- 找到真正实现“反馈 -> 适应 -> 新计划”闭环的项目，而不是只列一次性计划生成器；
- 给出 90 天最小验证路线和会导致停止/转向的反证门槛；
- 所有重要事实有一手来源，事实、作者主张和推断分开表述。

## Scope

- **Allowed paths**：只做外部研究；可引用本仓库和 GitHub issues #1、#2、#3。
- **Forbidden paths**：不修改代码、issue、仓库设置或产品数据。

## Verification

按下方“输出格式”逐项检查；项目表不少于 15 个，Top 深入拆解不少于 5 个，每项采用建议必须有许可证、活跃度、集成边界和退出条件。

## 可直接交给 ChatGPT Deep Research 的 Prompt

你是一名同时熟悉开源软件、LLM agent、数字健康、运动科学与产品研究的资深研究员。请做一次可审计的 deep research，帮助我决定 SportAgent 应该复用什么、舍弃什么，以及真正值得创新的部分是什么。

### 项目背景

SportAgent 当前是一个 Python/uv 项目，面向非临床成年人：

- 通过问答收集目标、经验、时间、器材、饮食和伤病禁忌；
- Planner Agent 生成周训练与宏观营养计划；
- Cooking Agent 生成逐日饮食并用确定性代码重算/约束热量与宏量营养；
- Gym Agent 生成单次训练执行指导；
- 使用本地结构化动作、食材、食谱、营养、伤病和热身知识库；
- 支持多个 LLM provider；
- 现阶段主要是“一次性计划生成器”，尚未形成真实反馈驱动的长期闭环。

项目的北极星是：

> 让普通训练者无需依赖昂贵的长期私教，也能获得安全、可执行、会随真实反馈持续调整的个性化训练与营养指导，并取得可验证、可持续的身体与行为进步。

计划中的 v1 是一个为期四周的训练闭环：为健康的初级到中级成年人生成首周力量训练计划，采集每次训练和每周的完成度、RPE/RIR、疼痛、睡眠、体重/围度与表现反馈，然后在确定性安全边界内推进、维持、降载、替换动作、重规划或转介。完整营养/食谱闭环暂不属于 v1 主验证面。

### 核心判断框架

请严格区分两类能力：

#### A. 基础设施：优先采用维护良好的开源项目

Agent/runtime 编排、模型路由与重试、RAG/vector storage、通用知识库管理、任务调度、日志/trace/observability、通用 eval runner、实验追踪、用户数据存储、同步、通知、通用 UI 外壳和部署。

#### B. 核心创新：SportAgent 应保留并形成证据壁垒

健身领域的约束推理、在计划修订时保持未受影响约束、真实反馈驱动的闭环适应、确定性安全边界，以及衡量安全性、可执行性、依从性、个性化质量和真实进步的领域评测与 oracle。

不要因为某项能力已经写在现有代码里就把它判定为核心；也不要因为某个项目流行就建议采用。判断标准是：是否直接形成 SportAgent 的领域差异、是否可验证、是否已有成熟通用实现、集成成本是否低于维护成本。

### 研究问题

1. 截至研究当日，全球有哪些与 SportAgent 直接相似或强相关的开源项目、商业产品、研究原型和论文？
2. 哪些项目真正实现了“反馈 -> 适应 -> 新计划”的长期闭环，而不只是生成一次性计划或提供聊天界面？
3. 它们如何表示用户状态、训练计划、动作、check-in、疲劳/恢复、疼痛、安全约束和适应决策？
4. 它们的适应机制属于规则、优化算法、推荐系统、传统 ML、LLM，还是混合系统？关键决策是否可解释、可重复、可审计？
5. 它们如何评测安全、有效性、依从性、留存和真实身体结果？是否有公开数据、对照实验、用户研究或临床/运动科学证据？
6. 哪些开源项目适合直接承担 SportAgent 的基础设施？哪些只能参考领域模型或数据结构？哪些看似相关但不应采用？
7. 当前生态中最重要、尚未被很好解决的空白是什么？SportAgent 最窄、最可证伪、最有价值的创新切入点是什么？
8. 为了在 90 天内验证核心假设，SportAgent 应该 adopt、wrap、retain、rewrite、delete 哪些部分？

### 搜索范围

至少覆盖并明确分类：

- 开源 AI fitness coach / workout planner / adaptive training；
- 开源训练日志、健身追踪、动作库、营养规划与 meal planning；
- 个性化推荐、periodization、auto-regulation、RPE/RIR、fatigue/recovery 模型；
- LLM 在运动处方、数字健康 coaching、营养建议和安全 guardrail 中的研究；
- 可复用的 agent/LLM 基础设施，但只保留与 SportAgent 具体需求匹配的候选；
- 商业产品仅用于能力与用户体验对标，不把无法验证的营销文案当证据。

主动使用多组中英文关键词和同义词搜索；不要只围绕我已经知道的项目。优先 GitHub、项目官网/文档、正式论文、作者页面、官方 benchmark 和公开产品文档。

### 证据要求

- 每个重要事实都给直接链接，优先一手来源；
- 对 GitHub 项目记录 repo、许可证、主要语言、最近 release/commit、维护活跃度、issue/PR 健康、部署方式和扩展接口；
- 对论文记录年份、任务、数据、方法、对照、样本量、指标、局限和是否有代码；
- 对商业产品区分“官方宣称”与“独立证据”；
- 明确标注事实、作者主张和你的推断；
- 对没有证据的功能写“未找到公开证据”，不要补全；
- 检查许可证、数据隐私、医疗/健身安全、项目停更、供应商锁定和维护负担；
- 说明检索日期和信息可能失效的位置。

### 输出格式

#### 1. 执行摘要

用不超过 10 条结论回答：生态现状、最强可复用项目、真正空白、SportAgent 应聚焦的核心假设，以及最重要的反证风险。

#### 2. 项目全景表

列出 15–30 个高相关项目：

| 项目 | 类型 | 直接/相邻 | 目标用户 | 闭环适应 | 安全机制 | 评测证据 | 开源/许可证 | 活跃度 | 可复用部分 | 主要缺口 | 结论 |

不要用 star 数代替质量判断。

#### 3. Top 5–8 深入拆解

对最值得借鉴或采用的项目逐个分析：架构、数据模型、适应机制、扩展点、运行成本、许可证、维护风险、与 SportAgent 的集成边界，以及 adopt/wrap/avoid 结论。

#### 4. 基础设施外包矩阵

| 能力 | SportAgent 当前做法 | 首选开源项目 | 备选 | 集成边界 | 迁移成本 | 许可/锁定风险 | adopt/wrap/delete |

#### 5. 核心创新与竞争空白

给出一张“已有项目做得好 / 仍未解决 / SportAgent 可证伪假设”的 gap map。指出哪些所谓创新实际上是通用能力，哪些领域能力可能形成真正壁垒。

#### 6. 90 天建议

给出按 0–30、31–60、61–90 天划分的最小路线，必须以验证核心假设为中心；列出应删除或停止自研的基础设施、需要保留的领域代码、要建立的 baseline、数据集、oracle 和实验门。

#### 7. 反方结论

认真回答：“为什么 SportAgent 可能不值得做，或者为什么当前北极星/切入点是错的？”给出会使你建议停止、转向或缩小范围的证据门槛。

#### 8. 来源

按“开源项目 / 论文 / 官方产品资料 / 其他”分组列出所有来源和访问日期。

### 最终要求

结论必须能指导真实的 build-vs-buy 和产品范围决策，而不是项目链接清单。优先指出可以删除的工作、可用薄适配器接入的基础设施，以及最小可运行实验。对于不确定项，给出下一步最便宜的验证方式。
