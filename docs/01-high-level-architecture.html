System Architecture

AI 健身系统

基于 LLM/VLM 的个性化健身管理系统。两个核心 Agent，三个开发阶段，一个目标：让用户只需要执行。
01 两个核心 Agent
🏗️
规划 Agent
LLM-POWERED · PLANNING & SCHEDULING
负责整个健身生命周期的规划与管理。从用户的身体信息、目标、日程出发，生成多粒度的训练计划和营养方案（年 → 月 → 周 → 日 → 餐/动作级别）。通过与用户的持续交互，动态调整计划以适应现实变化。核心子 Agent 包括 CookingAgent（饮食规划）、GYMAgent（训练编排）和 KBAgent（知识库自进化）。
协 同
👁️
视觉 Agent
VLM-POWERED · VISUAL FEEDBACK
负责实时的视觉理解与反馈。通过视频分析用户的训练动作，识别动作类型并与金标准对比，给出具体的纠正建议。通过食物照片识别食材和估算热量。通过定期体态照片追踪身体变化。视觉 Agent 的输出会反馈给规划 Agent，形成完整的闭环。
02 三个开发阶段
Phase 1
当前阶段
规划 Agent
独立完成规划 Agent 的全部能力。从静态计划生成（v0.1.x）到用户交互调整（v0.2.x）再到知识库自进化（v0.3.x）。目标：仅靠文本交互就能为用户提供完整的、可执行的、动态调整的健身方案。
PlanAgent CookingAgent GYMAgent KBAgent 用户交互 日程感知
Phase 2
规划中
视觉 Agent
独立完成视觉 Agent 的核心能力。训练动作的识别与纠正、食物照片的识别与热量估算、体态变化的追踪。目标：让系统具备"眼睛"，能理解用户的真实执行质量。
动作识别 动作纠正 食物识别 热量估算 体态追踪
Phase 3
规划中
双 Agent 联合
将规划 Agent 和视觉 Agent 深度整合。视觉 Agent 的发现自动反馈给规划 Agent（如：动作偏差 → 调整训练计划，饮食拍照 → 自动更新营养记录）。达到"用户只负责执行"的终极目标。
双Agent协同 自动反馈闭环 全自动调整 伤病预防
03 Phase 1 路线图：规划 Agent
v0.1.0 · 静态规划 — 基础计划生成
用户初始化 + Plan 生成
用户通过问答输入个人信息（身体数据、目标、器材、伤病、饮食限制、作息）。PlanAgent 基于知识库生成个性化的周训练计划和每日营养方案。包含"生成-验证-修正"多轮循环确保计划质量。
PlanAgent
v0.1.x · 静态规划 — 精细化 Guidance
CookingAgent + GYMAgent 细粒度指导
在基础 Plan 之上，由专门的子 Agent 生成更细粒度的指导。CookingAgent 负责具体食谱（烹饪步骤、食材替换、采购清单）。GYMAgent 负责训练细节（动作执行要点、每周渐进参数、热身拉伸方案）。Plan 是骨架，Guidance 是血肉。
PlanAgent CookingAgent GYMAgent
v0.2.x · 动态交互 — 用户纠正与调整
对话式调整 + 牵一发动全身
允许用户通过对话纠正和调整 Plan/Guidance 的内容（"今天想吃面条"、"周三要加班没法练"）。关键挑战：一个局部修改往往需要全局调整——比如减少一天的训练量需要重新分配周训练量，改变一餐饮食需要调整其他餐的营养配比。Agent 需要自动完成这些级联调整并记录。
PlanAgent CookingAgent GYMAgent UserDialog
v0.2.x · 动态交互 — 日程感知
日历 / 经期 / 工作日程集成
通过导入 ICS 文件或日历 API，Agent 能感知用户的真实日程——会议密集的工作日安排轻量训练、出差期间切换为酒店可执行的徒手方案、经期自动调整训练强度和营养策略。系统从"用户告诉我变化"进化为"我主动感知变化"。
PlanAgent CalendarSync
v0.3.x · 自进化 — 知识库自动更新
KBAgent：从互联网学习 + 用户偏好适配
KBAgent 负责知识库的持续进化，包含两个方向：（1）从互联网、书籍、论文中获取最新的营养学、运动科学知识，经过验证后纳入知识库；（2）根据用户的历史对话和偏好反馈，主动调整知识储备的侧重——比如用户经常问素食相关问题，KBAgent 会主动丰富素食营养知识。
