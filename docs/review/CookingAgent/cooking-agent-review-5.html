02 多样性分析：v4 核心矛盾已解决
📊v4 vs v5 对比
v4：15 道菜，5 道各出现 3 次，AB 模板交替循环
v5：27 道菜，0 道出现 ≥3 次，8 道出现 2 次

这是精确性与多样性 trade-off 的完美解法：不是牺牲精确性来换多样性，而是扩充了"已验证食谱库"，让 agent 有更多安全选项可以轮换。
🥩蛋白质来源 11 类
鸡胸肉、鸡腿、牛里脊、牛腹肉、猪里脊、火鸡、三文鱼、鳕鱼、虾、金枪鱼、豆腐/毛豆/大豆。覆盖了禽、畜、海鲜、植物蛋白四大类。火鸡肉是新增亮点——高蛋白低脂肪，中国市场可得性虽然有限但在大型超市可以找到。
🍳菜品创新点
火鸡肉酿彩椒、高蛋白松饼（燕麦+鸡蛋+香蕉）、金枪鱼意面沙拉、西兰花牛肉面、香蕉蛋白奶昔（纯蛋白+水）、奇亚籽隔夜燕麦、豆浆香蕉杏仁杯。这些菜品在保证营养精度的同时，提供了中西结合的多样口味。烹饪方式覆盖了蒸、煎、烤、炒、拌、焖。
03 遗留问题
🔴训练日数据流仍然断裂（连续两版）P0
PlanAgent 输出 5 个训练日（周一至周五），但 CookingPlan v5 仍然将全部 7 天标为休息日。这意味着：

• 训练日缺少 pre_workout（训练前 90 分钟的加餐）和 post_workout（训练后 60 分钟的高蛋白餐）
• 训练日热量目标应该更高（约 2672 kcal vs 当前的 2397 kcal），差距约 275 kcal/天
• 用户在训练日会少吃约 275 kcal，影响恢复和增肌效果

这是当前整个系统最紧急的 bug。PlanAgent 已经为每个训练日写好了"训练前饮食"和"训练后饮食"建议，CookingAgent 应该基于此安排 pre/post_workout 餐食。需要检查：① PlanAgent 的输出格式中是否包含结构化的训练日信息？② CookingAgent 的输入解析是否正确读取了这个信息？
🟠周三蛋白质 139.5g — 差 0.5g 未达标P1
周三是豆腐为主的一天（家常豆腐炒蔬菜 32g 蛋白质），植物蛋白天蛋白质总量偏低是合理的。但 0.5g 的差距说明修正循环的蛋白质检查阈值可能刚好卡在边界上。建议将蛋白质验证阈值设为 145g（留 5g buffer），这样修正循环会自动调整食材用量来补足。
🟠周一热量 +9.1% — 可控但在边界P1
周一的实际计算热量 2614 kcal，比目标 2397 高 9.1%，刚好在 ±10% 以内。主要原因是两个 snack 都偏大（莓果鸡蛋坚果碗 433 kcal + 香蕉鸡蛋燕麦昔 512 kcal）。系统自检已经正确检测到这些 snack 超过 350 kcal 的建议上限。修正循环应该在检测到 snack ≥400 kcal 时自动减少食材用量。
🟡系统自检标注 vs 实际计算不一致P2
系统自检报"6/7 天热量达标"，但确定性验算显示 7/7 天达标。原因：自检使用 LLM 标注值（偏高 3-5%），导致周一被标注为 2714 kcal（+13.2%），超过了 10% 阈值。但实际计算值是 2614 kcal（+9.1%），在 10% 以内。

这个偏差方向是安全的（自检比实际更严格），但说明修正循环的判断依据和实际营养数据库之间仍有 gap。长期来看需要接入确定性数据库替换 LLM 估算。
🟡"莓果鸡蛋坚果碗" — 口味搭配存疑P2
水煮蛋切块 + 蓝莓 + 草莓 + 杏仁 + 蜂蜜，放在一个碗里吃——从营养角度完美，但口味搭配比较挑战（咸鸡蛋 + 甜莓果）。类似 v3 的"煮熟鸡蛋打奶昔"问题。建议加入食谱合理性检查规则：鸡蛋类和甜味水果不应该在同一道菜中混合（除非是烘焙类如松饼）。
🟡香蕉蛋白奶昔 — 170g 蛋白需要 6-7 个蛋P2
周四的"香蕉蛋白奶昔"需要 170g 蛋白（约 6-7 个鸡蛋只取蛋白），剩余的蛋黄浪费问题和操作复杂度都偏高。建议用蛋白粉（乳糖不耐受可用大豆分离蛋白粉）替代纯蛋白——一勺蛋白粉 ≈ 25g 蛋白质，操作简单且不浪费蛋黄。
04 做得非常好的地方
🎯精度+多样性同时达标
v4 的核心矛盾是"精确但无聊"。v5 证明了这不是不可调和的——通过扩充食谱库，agent 可以在保持 100% 标注精度的同时提供 27 道不重复菜品。这是架构层面的突破。
📏LLM 标注精度跃升至 100%
35 道菜全部在 ≤15% 偏差内，绝大多数在 ±10% 以内。最大偏差是虾仁蛋炒饭的 +13.8%（可能因为虾仁水分含量估算差异）。这说明 LLM 的热量估算能力在修正循环的训练下已经非常可靠。
✅乳糖限制完全合规
整周没有任何乳制品出现。豆浆替代牛奶，椰子油替代黄油，蛋白替代蛋白粉（v4 用了"无乳糖希腊酸奶"这种边界案例，v5 完全避免了）。所有"奶昔"实际都是蛋白+水+水果。
🛒系统自检功能成熟
自检正确识别了：热量偏差（周一 +13.2%）、日内蛋白质重复（周一鸡蛋 3 次）、snack 热量超标（5 个 snack）。虽然基于 LLM 标注值而非计算值，但检测方向正确，对用户有参考价值。
05 下一步改进路线图
1.修复训练日数据流（最高优先级）P0
这是连续两版（v4、v5）的同一个 bug，阻塞了整个系统的核心价值。

具体排查路径：
① PlanAgent 输出检查：plan.md 中是否有结构化的 training_days 和 rest_days 字段？目前看到的是"休息日: 周六, 周日"这行文本，但 CookingAgent 可能需要更明确的结构化数据。
② CookingAgent 输入检查：它接收到的 input 中是否包含训练日信息？是否有解析训练日的代码逻辑？
③ 预期结果：周一-周五应标记为训练日，每天增加 pre_workout（训练前 90 分钟，~400 kcal）和 post_workout（训练后 60 分钟，≥35g 蛋白质），总热量目标提升至约 2672 kcal。
2.蛋白质验证 buffer 从 140g 提升至 145gP1
周三 139.5g 差 0.5g 未达标。如果修正循环的蛋白质检查目标设为 145g，它会在生成阶段自动补足（比如把家常豆腐从 240g 增加到 280g，或加一个水煮蛋），避免边界情况。
3.snack 热量硬上限 400 kcalP1
系统自检已经检测到 5 个 snack 超过 350 kcal，但没有触发修正。建议将 snack 热量上限从"建议 350"改为"硬限制 400"——超过 400 kcal 的 snack 自动触发食材减量。这可以防止周一那样两个 snack 合计接近 1000 kcal 的情况。
4.食谱合理性检查（口味搭配）P2
"莓果鸡蛋坚果碗"（咸鸡蛋+甜莓果+蜂蜜）的口味搭配存疑。建议加入简单的食谱合理性规则：水煮蛋/煎蛋不与甜味水果+蜂蜜同碗。替代方案：把鸡蛋换成希腊风（不，乳糖不耐受）→ 换成燕麦或奇亚籽。
5.大豆分离蛋白粉替代纯蛋白P2
周四"香蕉蛋白奶昔"需要分离 6-7 个蛋的蛋白——操作复杂且浪费蛋黄。PlanAgent 已经在补剂建议中列出了"无乳糖蛋白粉"。CookingAgent 应该利用这个信息，在奶昔/smoothie 类食谱中优先使用蛋白粉替代纯蛋白。

A-：CookingAgent 的生成质量已达到可交付水平

v5 同时实现了热量 7/7 达标（确定性验算口径）、标注精度 100%（35/35）、27 道唯一菜品（0 道 ≥3 次）、11 类蛋白质来源、乳糖限制完全合规。这解决了 v4 "精确但无聊"的核心矛盾——证明精确性和多样性可以同时达到。

从 v1 到 v5 的演进路径清晰：v1-v2 解决基础精度 → v3 引入修正循环 → v4 精度达标但多样性崩塌 → v5 精度+多样性同时突破。每一版都在前一版的问题上做了针对性改进，agent 的学习曲线健康。

但系统整体还不能交付，因为训练日数据流连续两版断裂。即使 CookingAgent 自身质量再高，如果训练日全部按休息日生成饮食，用户在训练日就会少吃 ~275 kcal、缺少训练前后的针对性营养。这个问题不在 CookingAgent 内部，而在 PlanAgent → CookingAgent 的数据传递环节——修复它是从 A- 到 A 的最后一步。
