🐛 核心 Bug：面条"干面重量" vs "熟面重量"混淆

v7 的面条菜品配方标注为"干面重量"（如"面条 280g (干面重量)"），但 LLM 的热量估算按"熟面重量"来计算。干面和熟面的热量密度差 2.5 倍（干面 348 kcal/100g vs 熟面 138 kcal/100g）。

影响范围：
• 周三 西兰花牛肉面：280g 干面 = 974 kcal（标注 826，LLM 按熟面估算约 386 kcal）→ 实际全菜 1503 kcal vs 标注 826（-45% 偏差）
• 周二 训练后虾仁汤面：130g 干面 = 452 kcal → 额外多出 273 kcal
• 周五 训练后虾仁汤面：200g 干面 = 696 kcal → 额外多出 420 kcal

根因：LLM 对"大米"一贯标注"煮熟后重量"，但对"面条"改为了"干面重量"——同一份计划内重量基准不统一。大米用熟重（因为用户量的是煮好的饭），面条却标了干重（因为面条包装标的是干重）。这种不一致让 LLM 的热量估算和实际计算产生了严重偏差。

解法：统一所有主食为同一种重量基准。推荐统一用熟重——这是用户实际称量时最方便的方式。如果配方要写干面，则必须同时标注生熟比（面条 1:2.5，大米 1:2.3），并用熟重计算热量。

02 v7 新特性（改进项）
✅蛋白粉首次出现
周四"训练前燕麦香蕉蛋白奶昔"使用了乳清蛋白粉 20g (无乳糖版本)，且出现在采购清单中。这解决了连续两版（v5、v6）的"需要 7 个蛋的蛋白"问题。PlanAgent 的补剂建议被 CookingAgent 正确读取和使用。
✅豆腐甜品碗替代"莓果鸡蛋坚果碗"
"豆腐莓果碗（无乳糖版）"和"豆腐蓝莓核桃碗（无乳糖版）"——嫩豆腐压成酸奶质地 + 莓果 + 坚果 + 蜂蜜。解决了 v5 的"水煮蛋+莓果+蜂蜜口味冲突"问题，且明确标注"无乳糖版"。
✅31 道唯一菜品（历史最高）
v5 的 27 道 → v6 的 26 道 → v7 的 31 道。新增了烤鸡腿配红薯芦笋、豆腐菠菜燕麦早餐碗、虾仁蔬菜炒饭、苹果配杏仁、盐水毛豆配杏仁等。0 道菜出现 ≥3 次。
✅周二早餐 = 三明治+燕麦粥+香蕉
"蔬菜鸡蛋全麦三明治"实际是一个组合早餐（燕麦粥+三明治+香蕉），654 kcal 提供充足能量。虽然菜名没完全反映配方，但作为一餐完整的训练日早餐很合理。
03 需要修复的问题
1.统一所有主食为熟重标注P0
当前大米标注"煮熟后重量"，面条标注"干面重量"——同一份计划内基准不一致。必须统一为熟重，这是用户实际称量最方便的方式。面条改为"面条 XXg（煮熟后重量）"即可。这个 bug 影响了 3 天的热量准确性。
2.周二蛋白质 138g — 差 2g 未达标P1
周二的蛋白质主要来源偏少：虾仁 120g（22g pro）+ 鳕鱼 200g（36g pro）+ 鸡蛋共 120g（16g pro）。嫩豆腐的蛋白质密度较低（5g/100g vs 老豆腐 8g）。建议将豆腐莓果碗的嫩豆腐改为老豆腐，或增加虾仁到 150g。
3."年糕"菜名仍未修正P2
连续两版出现——配方是米饭捏饭团，菜名叫"年糕"。这不影响功能，但影响用户理解。
4.高蛋白松饼仍用 6 个蛋白（180g）P2
周四的奶昔已经用了蛋白粉，但周三的松饼仍然使用 180g 蛋白（~6 个蛋清）。建议松饼也改用蛋白粉——燕麦粉+鸡蛋+香蕉+蛋白粉的松饼同样可行。

💡建议：修一个 bug 后转向其他方向
CookingAgent 的核心功能已经 90% 完成。剩下的提升空间主要是：

必须修（1 个快速修复）：统一面条/大米的生熟重量标注为"熟重"。这是一个 prompt/规则层面的修复，改动量小但影响大——修完之后 v7 的面条日就不会再有热量偏差。

建议暂缓（长期优化）：食物营养数据库接入、等营养素替换矩阵、备餐建议、采购清单优化。这些会让 CookingAgent 从 A- 到 A+，但边际收益递减——每个改进对用户体验的提升越来越小。

更有价值的方向：系统中其他 Agent 可能还在更早期的阶段。把时间投入到其他尚未打磨的 Agent（如 ProgressTracker、AdaptationAgent）上，ROI 会更高。CookingAgent 已经可以生成用户能直接跟着执行的周饮食计划了——这是它的核心使命。

A-：新特性出色，但面条生熟重量 bug 拉低了分数

v7 在新特性上做得很好：蛋白粉首次出现、豆腐甜品碗替代了口味冲突的鸡蛋莓果碗、31 道唯一菜品创新高。这些都是对之前 review 反馈的精准响应。但面条类菜品的"干面重量 vs 熟面重量"混淆是一个新引入的系统性 bug——它让 3 天中有面条的菜品热量计算全部偏离。

好消息是修复很简单：在 prompt 或验证规则中加一条"所有主食（大米、面条、藜麦）统一标注煮熟后重量"即可。这个修复完成后，v7 的实际水平应该回到 v6 的 A 级甚至更高（因为有蛋白粉、豆腐碗等新特性加持）。

关于是否继续改进 CookingAgent：建议做完"统一生熟重量"这一个快速修复后，CookingAgent 就可以暂时告一段落了。它的核心功能（训练日/休息日区分、pre/post workout、热量达标、多样性、乳糖限制）已经全部就位。剩余的优化（数据库、替换矩阵、备餐建议）是锦上添花——把时间投入到系统中其他 Agent 上会有更高的 ROI。
